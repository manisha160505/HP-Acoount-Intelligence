# Observability. The app degrades cleanly without these - every OpenTelemetry
# import is deferred into a function body and guarded, so a missing package
# turns tracing or metrics off and logs one line rather than failing to start.
# Structured JSON logging has no third-party dependency and always works.
#
# Floated within a major version deliberately: the instrumentation packages
# track the SDK closely and pinning one without the others is what produces
# the version-mismatch errors the guards above exist to survive.
opentelemetry-api>=1.27,<2
opentelemetry-sdk>=1.27,<2
opentelemetry-instrumentation-fastapi>=0.48b0

# Google Cloud. Only needed where GCP_PROJECT_ID is set; a local run without
# them still traces (spans stay in-process and correlate the logs) and still
# writes JSON logs, which is all Cloud Logging needs once the container's
# stdout is collected by the platform's built-in agent.
opentelemetry-exporter-gcp-trace>=1.7
# The `a0` is load-bearing - do not "tidy" it to >=1.7.
#
# Google has never published a final release of the monitoring exporter: every
# version from 1.0.0a0 to 1.15.0a0 is an alpha, while its sibling above has 16
# stable ones. A specifier naming no pre-release can only match a final
# release, so `>=1.7` matched nothing and failed the install outright - which
# broke every Render deploy from the commit that added this line onwards.
#
# Naming a pre-release makes pre-releases eligible for this requirement under
# PEP 440, in every resolver. The instrumentation pins above already rely on
# the same rule with their `0.48b0`.
#
# It was not caught in CI because pip falls back to allowing pre-releases when
# no final release satisfies a specifier, and GitHub's pip applied that
# fallback while Render's did not. A green CI run is not evidence that this
# line is correct.
opentelemetry-exporter-gcp-monitoring>=1.7.0a0

# Exporting to a non-Google OTLP collector instead of, or alongside, the above.
opentelemetry-exporter-otlp-proto-grpc>=1.27,<2
